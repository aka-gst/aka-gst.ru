Приложение A. Быстрая диагностика Windows

Используйте команды только для локальной диагностики. Они не исправляют проблему автоматически и не должны заменять экспериментальный prompt.

Windows sandbox fallback

Предпочтителен elevated sandbox. Если его setup не работает из-за политики или отсутствия прав, официальный fallback задаётся в %USERPROFILE%\.codex\config.toml. Не дублируйте секцию [windows].

json
[windows]
sandbox = "unelevated"

Не используйте full access как постоянное лечение. Сначала обновите Codex, повторите setup и проверьте официальный unelevated fallback.

Приложение B. Безопасное обезличивание

Перед сохранением evidence замените персональные данные, но не меняйте технический смысл ошибки. Всегда храните оригинал локально только если он действительно нужен; в Git помещается только безопасная копия после отдельного решения.

PromptСохранять только тестовую формулировку без личного контекста.

Приложение C. Prompt сравнения двух аудитов

Запускайте после того, как оба независимых отчёта уже получены. Сравнение не должно переписывать отчёты и выбирать вывод по стилю ответа.

ГОТОВЫЙ PROMPT

Сравни два приложенных независимых аудита Open-LLM-VTuber.

Создай таблицу:
Тема | Отчёт 1 | Отчёт 2 | Совпадение/расхождение |
Команда локальной проверки | Проверенный итог.

Не выбирай утверждение по уверенности формулировки. Каждое расхождение проверь read-only командой по локальным файлам. Если проверить нельзя, поставь NOT PROVEN. Не читай evidence, .env и секреты. Ничего не изменяй. В конце выполни git status --short.

Когда аудит считается независимым

  • Новая сессия Codex.
  • Первый отчёт не передан и запрещено читать evidence.
  • Формулировка задачи отличается.
  • Финальные расхождения проверяются командами, а не третьим мнением модели.

Приложение D. Definition of Done

Финальный review prompt

Проведи read-only review итогов практикума по Definition of Done.
Для каждого пункта верни PASS / FAIL / NOT PROVEN и ссылку на конкретное доказательство.
Не считай словесное утверждение тестом. Не читай секреты и PII.
Отдельно проверь source tree VTuber, gateway auth/allowlist, локальность ASR/TTS,
отсутствие feedback loop и target PR. Ничего не изменяй.
