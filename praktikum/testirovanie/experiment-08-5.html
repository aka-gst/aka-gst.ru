Атомарная цель. Сопоставить уже выполненные эксперименты 1-8 с критериями и повторить только недостающие доказательства.

Что мы делаем и зачем

Контрольная точка предотвращает две крайности: слепой повтор всей работы и необоснованное предположение, что старый результат соответствует новой методике. Статус «работает» отделяется от статуса «доказано по критерию».

Что должно быть готово

  • Собраны доступные логи, скриншоты и Git-история предыдущей работы.
  • Никакие старые файлы автоматически не удаляются.

Где выполнять

Read-only Codex в корне Open-LLM-VTuber. Артефакты передаются выборочно и без секретов.

Scope

РазрешеноТолько действия, прямо указанные в prompt и командах этого эксперимента.
ЗапрещеноСекреты, изменение main/upstream, расширение scope и скрытое исправление новых ошибок.
РезультатАртефакты и критерии на третьей странице эксперимента.

Откройте Codex из папки, указанной на предыдущей странице. Для независимого аудита обязательно создайте новую сессию. Скопируйте следующий prompt целиком, не вырезая ограничения.

PROMPT ДЛЯ CODEX - КОПИРОВАТЬ ЦЕЛИКОМ

Проведи read-only checkpoint экспериментов 1-8. Не меняй файлы и не исправляй историю.

Для каждого эксперимента создай строку: требование, найденное доказательство, PASS/FAIL/NOT PROVEN, чего не хватает, минимальная команда повтора. Не считай словесное утверждение тестом.

Отдельно проверь три возможных отклонения: менялся ли source ради pyttsx3; были ли evidence committed в репозиторий; был ли PR направлен в upstream вместо собственного fork. Не удаляй и не закрывай ничего без нового scope.

В конце выведи только список минимальных повторов и git status --short.

Команды PowerShell

Команды ниже нужны либо для ручного выполнения, либо для сверки предложения Codex. Строки после комментария «после подтверждения» не запускаются заранее.

КОМАНДЫ - КОПИРОВАТЬ ПО ПОРЯДКУ

bash
git status --short
git log --oneline -10
git diff --stat
git remote -v
git branch --show-current

Как действовать при запросе разрешения

Прочитайте команду и рабочую папку; сразу сверьте их со scope этого эксперимента.

Для одной безопасной команды выберите разовое Yes, proceed.

Если команда читает секреты, пишет за пределами scope или меняет main - нажмите Esc и объясните ограничение.

Что должно получиться

  • Матрица содержит восемь экспериментов.
  • Для каждого NOT PROVEN указана одна минимальная проверка.
  • Отклонения описаны без автоматического исправления.

Типовые ошибки и действия

  • Старое evidence содержит персональные данные: редактировать копию, не оригинал.
  • Source менялся: эксперимент может быть функционально успешен, но критерий source unchanged остаётся FAIL.
  • PR target неверен: требуется отдельное решение, не silent rewrite history.
