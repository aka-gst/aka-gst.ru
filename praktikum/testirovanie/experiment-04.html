Атомарная цель. Получить вторую архитектурную карту другой формулировкой и проверить расхождения командами.

Что мы делаем и зачем

Второй аудит снижает риск якорения на первом ответе. Важно не просить модель подтвердить уже готовую карту, а сформулировать задачу независимо. Совпадение двух ответов ещё не доказательство; финальным доказательством остаётся локальный файл или команда.

Что должно быть готово

  • Отчёт эксперимента 3 сохранён вне контекста новой сессии.
  • Рабочее дерево чистое.

Где выполнять

Новая сессия Codex из корня Open-LLM-VTuber. Не продолжать предыдущий чат.

Scope

РазрешеноТолько действия, прямо указанные в prompt и командах этого эксперимента.
ЗапрещеноСекреты, изменение main/upstream, расширение scope и скрытое исправление новых ошибок.
РезультатАртефакты и критерии на третьей странице эксперимента.

Откройте Codex из папки, указанной на предыдущей странице. Для независимого аудита обязательно создайте новую сессию. Скопируйте следующий prompt целиком, не вырезая ограничения.

PROMPT ДЛЯ CODEX - КОПИРОВАТЬ ЦЕЛИКОМ

Проведи независимый read-only аудит Open-LLM-VTuber. Не используй и не ищи отчёты предыдущих экспериментов.

Ничего не изменяй. Не читай .env, evidence, .git, .venv, node_modules, логи и backup-файлы. На основании инструкций, документации и кода составь архитектурную карту потока: запуск процесса -> загрузка и валидация конфигурации -> инициализация service context -> LLM/ASR/TTS -> WebSocket -> frontend.

Затем назови ровно три главных риска воспроизведения upstream baseline на Windows. Для каждого укажи категорию, локальное доказательство file:line, минимальную read-only проверку и безопасный способ устранения. Всё недоказанное пометь NOT PROVEN.

В конце выполни git status --short. Не сравнивай результат с первым аудитом.

Команды PowerShell

Команды ниже нужны либо для ручного выполнения, либо для сверки предложения Codex. Строки после комментария «после подтверждения» не запускаются заранее.

КОМАНДЫ - КОПИРОВАТЬ ПО ПОРЯДКУ

# После получения двух независимых отчётов - в отдельной сессии:
# передайте тексты как ОТЧЁТ 1 и ОТЧЁТ 2, затем используйте prompt сравнения из документа.
git status --short

Как действовать при запросе разрешения

Прочитайте команду и рабочую папку; сразу сверьте их со scope этого эксперимента.

Для одной безопасной команды выберите разовое Yes, proceed.

Если команда читает секреты, пишет за пределами scope или меняет main - нажмите Esc и объясните ограничение.

Что должно получиться

  • Получена вторая карта без ссылок на первый отчёт.
  • Названы ровно три Windows-риска.
  • После отдельного сравнения создана таблица совпадений и расхождений.

Типовые ошибки и действия

  • Вторая сессия видит evidence: явно запретить чтение evidence.
  • Модель выбирает победителя по уверенности: потребовать локальную команду проверки.
  • Отчёты различаются терминами, но не фактами: нормализовать названия компонентов.
