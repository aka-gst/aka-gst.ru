Атомарная цель. Зафиксировать исходное состояние Windows, инструментов, локальных моделей и Git-репозитория без изменения файлов.

Что мы делаем и зачем

Инвентаризация нужна как точка отсчёта. Если дальнейший запуск упадёт, вы сможете отличить исходную проблему окружения от ошибки, появившейся после настройки. Здесь не исправляют найденные проблемы внутри того же шага: сначала сохраняют факты и классифицируют их.

Что должно быть готово

  • Codex CLI запускается из PowerShell.
  • Рабочая папка C:\dev\agent-lab существует.
  • Не требуется запускать Open-LLM-VTuber или менять conf.yaml.

Где выполнять

Обычный PowerShell: C:\dev\agent-lab. Затем новая сессия Codex из этой же папки.

Откройте Codex из папки, указанной на предыдущей странице. Для независимого аудита обязательно создайте новую сессию. Скопируйте следующий prompt целиком, не вырезая ограничения.

PROMPT ДЛЯ CODEX - КОПИРОВАТЬ ЦЕЛИКОМ

Проведи read-only инвентаризацию среды C:\dev\agent-lab.

Ничего не изменяй. Не читай и не выводи содержимое .env, токенов, SSH-ключей, cookies, keychain и других секретов. Не печатай персональные абсолютные пути; заменяй каталог пользователя на %USERPROFILE% или %LOCALAPPDATA%.

Проверь реальные версии Git и uv, состояние GitHub CLI без значения token и scopes, список Ollama-моделей, найденные Git-репозитории и git status --short каждого из них. Если команда завершилась ошибкой, покажи exit code и классифицируй ошибку как environment, configuration, dependency или source.

Ничего не исправляй в этом шаге. В конце создай компактную таблицу: проверка, фактический результат, PASS/FAIL, классификация. Подтверди, что файлы не изменялись.

Команды PowerShell

Команды ниже нужны либо для ручного выполнения, либо для сверки предложения Codex. Строки после комментария «после подтверждения» не запускаются заранее.

КОМАНДЫ - КОПИРОВАТЬ ПО ПОРЯДКУ

powershell
Set-Location C:\dev\agent-lab
git --version
uv --version
gh auth status
ollama list
Get-ChildItem -Directory -Force | Where-Object { Test-Path (Join-Path $_.FullName '.git') }
git -C .\Open-LLM-VTuber status --short

Как действовать при запросе разрешения

Прочитайте команду и рабочую папку; сразу сверьте их со scope этого эксперимента.

Для одной безопасной команды выберите разовое Yes, proceed.

Если команда читает секреты, пишет за пределами scope или меняет main - нажмите Esc и объясните ограничение.

Что должно получиться

  • Git и uv печатают версии и exit code 0.
  • gh auth status сообщает успешный вход, но в отчёт не копируется строка Token.
  • ollama list показывает qwen3-vl:4b или честно фиксирует отсутствие модели.
  • git status --short не печатает строк для чистого рабочего дерева.

Типовые ошибки и действия

  • orchestrator_helper_launch_failed: обновить Codex CLI и повторить минимальный Get-Location.
  • Invalid GitHub token: выполнить gh auth login в обычном PowerShell и повторить только проверку.
  • Ollama не может писать лог из sandbox: запустить ollama serve вне sandbox и разрешить агенту только ollama list.
