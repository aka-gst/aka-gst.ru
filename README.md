# aka-gst.ru

Портфолио и витрина проектов. Статика под Caddy, без сборщика и зависимостей.

## Как устроено

Страница не пишется руками. Источник — два JSON, из них `build.mjs` собирает
`index.html`:

| Файл | Что описывает |
|---|---|
| `data/projects.json` | все проекты: треки, группы, статусы, ссылки, слаги аналитики |
| `data/site.json` | шапка, подвал, контакты, навыки и опыт |
| `data/qa-metrics.json` | снимок последнего прогона Local Agent Gateway |

Новый проект добавляется одной записью в `data/projects.json` — карточка,
строка в списке и событие аналитики появляются сами.

```sh
node build.mjs
```

Одна разметка и две оболочки поверх неё. Палитра переключается атрибутом
`data-track` на `<html>`: `work` — сдержанная, `play` — неоновая. Выбор
запоминается в `localStorage`, ссылки `#work` и `#games` открывают раздел
напрямую.

## Числа берутся из фидов, а не переписываются

Первый экран «Работы» рендерится из `data/qa-metrics.json`, который публикует
CI гейтвея. Сборка вклеивает снимок, `assets/app.js` поверх подтягивает живой
файл с GitHub Pages и заменяет значения. Если сети нет, остаётся снимок.
Карточки практикумов так же читают `praktikum/*/course.json`.

Смысл в том, что цифры на витрине — те же, что проверил прогон. Подробности
и схемы: `PORTFOLIO-FEEDS.md`.

Обновить всё, что сайт отдаёт, но не пишет сам:

```sh
sh sync-portfolio.sh
```

## Игры живут своими каталогами

`acid/`, `qa-quest/` и `avto/` — самостоятельные приложения на ванильных
модулях: сборка их не трогает, `build.mjs` знает о них только запись в
`data/projects.json`. У «Автоответчика» — экшена сверху вниз, где уровень
целиком помещается в строку кода, — свой разбор в `avto/README.md`, а бой
и ввод проверяются без браузера:

```sh
node avto/tests/sim.mjs
node avto/tests/input.mjs
```

Музыка игры пока синтезируется в браузере. Куда класть свои треки, чтобы
она переключилась на них, — `avto/music/README.md`.

Живёт «Автоответчик» в своём репозитории — [aka-gst/avtootvetchik][avto],
а `avto/` здесь его зеркало, как `acid/` для ACID UNO: выкладка копирует
дерево сайта, а не чужой git. Обновить копию после работы в игровом
репозитории:

```sh
rsync -a --delete --exclude '.git' --exclude '.githooks' --exclude '.gitignore' \
  ~/dev/avtootvetchik/ avto/
```

Правки, сделанные прямо здесь, зеркало затрёт — их место в игровом
репозитории, он источник.

[avto]: https://github.com/aka-gst/avtootvetchik

## Предпросмотр

```sh
python3 -m http.server 4180
```

`/tetcolor/`, `/knb/`, `/lines/` и `/coin/` локально отдадут 404: они живут
только на сервере.

## Выкладка

```sh
sh deploy.sh          # показать, что изменится
sh deploy.sh --go     # выложить
sh deploy.sh --go --caddy   # ещё и обновить конфиг Caddy
```

Список того, что едет на сервер, — **белый**, он задан в `deploy.sh`. Чёрный
список однажды забывает новое: так `.githooks/` с локальным списком личных
данных оказался в веб-корне только потому, что его не догадались исключить.
Новый файл на сайте — значит, его надо дописать в `PAYLOAD`.

`--delete` не используется: `coin/`, `lines/` и `knb/` выкладываются из своих
репозиториев и в этом дереве отсутствуют — иначе они были бы снесены.

### Caddyfile правят несколько проектов

В `/opt/zakriva/caddy/Caddyfile` пишет не только этот сайт: там же маршруты
звонков (`/meet/`, `meet.aka-gst.ru`), Лилы (`/leela/`) и сервиса аккаунтов
(`/api/auth/`, `/api/progress/`). Выкладка собранного у себя файла молча
удаляет чужие маршруты — так однажды уехали звонки.

`deploy.sh` перед выкладкой забирает живой файл и сравнивает. Собственные
добавления он пропускает, а строки, которые есть на сервере и нет у вас,
показывает и отменяет `--caddy`: их надо сначала перенести к себе.

### qa-quest/vendor

В `qa-quest/vendor/pyodide/` лежит около 13 МБ бинарников — Python, который
QA Quest выполняет в браузере. **В git они не версионируются** и добываются
скриптом: их источник — `tools/fetch-pyodide.sh` в репозитории QA Quest,
где зафиксированы версия и контрольные суммы всех пяти файлов.

Каталог пустой в свежем клоне — это нормально, а не пропажа. `deploy.sh`
добывает его сам перед выкладкой и проверяет, что на месте все пять файлов, а
не только `pyodide.mjs`: точка входа весит 18 КБ из 13 МБ, и её наличие ничего
не говорит о судьбе `pyodide.asm.wasm` на 9,6 МБ. Выкладка QA Quest вдобавок
сверяет sha256 всех пяти уже на живом домене.

Проверка нужна потому, что отказ здесь молчаливый: без локальной копии
приложение уходит за Python на чужой CDN и внешне продолжает работать.

Файлы были в репозитории до коммита `494a895`; блобы остались в истории —
переписывать её ради 12 МБ несекретных данных сочли несоразмерным.

## Проверка после выкладки

```sh
sh verify.sh
```

Проверяет боевой сайт: страницы отвечают 200, служебные файлы — 404, опечатка
в адресе даёт свою страницу с кодом 404, а выложенный `index.html` совпадает с
локальной сборкой.

Скрипт написан из трёх ошибок одного дня, и все три были ошибками проверки, а
не кода:

- `404` приняли за «защита работает», хотя файл просто ещё не выложили;
- ссылку на стиль искали по окончанию `.css` и не нашли `site.css?v=1`;
- «200 на главной» сочли доказательством, что страница цела.

Поэтому здесь ассеты берутся из самой страницы вместе со строкой запроса,
сверка идёт по содержимому, а `000` (ответа не было) отличается от `404`
(ответ «нет такого») — это противоположные выводы, и путать их нельзя.

## Защита от утечек

Репозиторий публичный, поэтому проверка на секреты и личные данные встроена в
`git`, а не держится на внимательности. Хук лежит в самом репозитории:

```sh
git config core.hooksPath .githooks
mkdir -p ~/.config/aka-gst && cp .githooks/private-words.example ~/.config/aka-gst/private-words.txt
chmod 600 ~/.config/aka-gst/private-words.txt
```

Список лежит **вне дерева сайта**: выкладка копирует файлы, а не индекс git,
поэтому в `.githooks/` он оказался бы на публичном сервере. Хук блокирует
коммит, если файл снова появится в дереве. Впишите туда имя, транслитерацию,
личную почту и телефон — пустой список означает, что проверка стоит, но
ничего не ищет.

Хук смотрит индекс целиком, а не только изменённые файлы: первая найденная
утечка лежала в файле, который в тот момент никто не трогал. Секреты ищутся по
форме ключа, поэтому проза вроде «Invalid GitHub token» не срабатывает, а
чужие публичные контакты в `psy-admin/` не блокируют коммит. Если сама
проверка сломается, коммит не пройдёт: молча пропустить хуже, чем ложно
остановить.

```sh
sh .githooks/test-pre-commit
```
